Arquitectura Técnica: Fyn

v2.0 - Serverless

1. Introducción

Fyn es una plataforma de gestión financiera inteligente que utiliza Inteligencia Artificial para asistir a los usuarios en el control de sus gastos, presupuestos y salud financiera a través de interfaces conversacionales (WhatsApp) y un panel web interactivo.

2. Stack Tecnológico

Backend Node.js ejecutado en un entorno Serverless (AWS Lambda). Escalabilidad automática y pago por uso.
Frontend Angular (v20+) desplegado en AWS S3 + CloudFront para una entrega de contenido global rápida.
Base de Datos Supabase (PostgreSQL) para almacenamiento relacional y gestión de autenticación de usuarios.
Inteligencia Artificial OpenAI y Groq SDK para el procesamiento de lenguaje natural y lógica de coach financiero.
Integraciones WhatsApp Business API para la interfaz de chat y Make.com para flujos de automatización externos.
Caché Redis (opcional) y Node-cache para optimizar tiempos de respuesta y manejo de estados.

3. Arquitectura de Sistema

La arquitectura de Fyn está diseñada bajo el paradigma de Microservicios Serverless, lo que permite manejar picos de tráfico sin necesidad de administrar servidores físicos.

[ Flujo de Datos ]

Usuario (WhatsApp) ↔ WhatsApp API ↔ AWS Lambda (Node.js) ↔ Supabase / IA

Usuario (Web) ↔ CloudFront (Angular) ↔ AWS Lambda / Supabase

Componentes Principales:

  • Lambda API: Maneja los webhooks de WhatsApp y las peticiones del frontend. Utiliza serverless-http para adaptar Express a Lambda.
  • Cron Jobs (Lambdas): Funciones programadas para tareas automáticas como dailyTips (9 AM COL) y monthlyFeedback (día 1 de cada mes).
  • Servicios (Business Logic): Lógica encapsulada en Services/ para suscripciones, métricas, perfiles y procesamiento de IA.

4. Seguridad y Autenticación

  • JWT (Supabase Auth): Todas las comunicaciones del frontend están protegidas mediante tokens de sesión.
  • Admin Secret: El panel de administración utiliza un secreto robusto definido en variables de entorno para proteger endpoints críticos (MRR, licencias).
  • Variables de Entorno: Gestión estricta de credenciales mediante AWS Lambda Environment Variables, evitando el almacenamiento de claves en el código fuente.

5. Escalabilidad y Rendimiento

El sistema aprovecha la infraestructura de AWS para garantizar alta disponibilidad:

  • AWS CloudFront: CDN que reduce la latencia del frontend y protege contra ataques básicos de red.
  • Lambda Concurrency: Capacidad para procesar cientos de mensajes simultáneamente gracias al auto-escalado de AWS.
  • Supabase Pooling: Conexión optimizada a PostgreSQL para manejar ráfagas de escrituras de transacciones.
